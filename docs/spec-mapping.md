## 機能（5章・6章）

| 仕様 | 実装 |
|---|---|
| 学習記録とアプリ起動記録を分ける | `daily_activity.open_count`（touch_open）と `completed_count`（完了時）を別に数える |
| 同じタスクを二度完了しても報酬は1回 | `complete_task` が完了済みなら記録しなおさない。台帳は `(source_type, source_id)` が一意 |
| 連続記録はタスク1件以上の完了、JST 24:00 締め | その日の最初の完了で進める。`nobit_daily_close`（JST 0:05）が前日を判定し、途切れたら current を 0 に、best は残す |
| 休息チケット・大会日は連続記録だけを守る | `nobit_rest_kind` が休息日を返し、連続の判定で飛ばす。学習日には数えない |
| 報酬はトランザクションで、コインは台帳に残す | `nobit_apply_completion` が1つのトランザクションで台帳・残高・日別記録・連続記録を更新する |
| クラブ管理者は自クラブだけ、自由登録の内容は見せない | RLS（`user_tasks_read` など）と、RPC の中の確認（`nobit_require_club`）の両方で守る |
| 生徒アプリに他の生徒の名前や順位を出さない | 生徒の RPC は自分の行だけを返す |
| アラートを出し、運営が手作業で送り、連絡済みを記録 | `alerts`・`alert_rules`、`nobit_alert_not_started`（毎時）、`nobit_daily_close`（記録が空いた）、完了時（連続記録の節目） |
| 将来の push への備え | `users.line_friend_status`（Webhook とログイン時に記録）、`users.line_contact_opt_in`、`alert_rules.delivery`（初期値 manual）、`alerts.retry_key`、保護者同意の文面 |
| 生徒は LINE ログイン、管理画面はメールリンク | `supabase/functions/auth-line`、`web/src/admin/Login.tsx` |
| 所属クラブは招待リンクで自動設定 | 招待QRの `?club=<招待コード>` を登録時に使う。生徒は入力しない |

## 実装で決めたこと（確認してください）

仕様書に書かれていない点、読み方が分かれる点は、次のように決めています。変える場合は教えてください。

1. **Phase 1 のコイン**：Phase 1 から台帳に記録し、画面には `VITE_PHASE=2` から出します。Phase 2 を公開したとき、それまでの頑張りがコインとして見えます。
2. **自由登録の「1日3件」**：記録できる件数の上限として扱いました。4件目は記録できません。
3. **クラブ管理者の追加・解除**：運営だけができます。クラブ管理者ができるのは、所属の承認と大会日の登録です。
4. **応援コメント**：クラブ管理者だけが送れます。運営は公式LINE のチャットで連絡します。
5. **LINE への連絡を止めた生徒**：アラートを出しません。生徒一覧の「対応が必要な順」には、記録の空き日数で引き続き並びます。
6. **未着手のアラート**：18時以降に、その日まだ1件も完了しておらず、運営設定のタスクが残っている生徒に出します。休息日は出しません。翌日の 0:05 に自動で閉じます。
7. **記録が空いたアラート**：記録のない日がちょうど3日になった日に1回だけ出します。休息日は数えず、承認前の日も数えません。
8. **1回だけのタスク**：開始日から期限まで毎日ホームに出て、完了した日の記録になります。
9. **自由登録の内容**：題名と教科の両方を、クラブ管理者には伏せます。件数だけ見せます。
10. **生徒一覧の「対応が必要な順」**：次の順で並べます。運営には、未対応のアラートがある生徒を少し上げます。
    1. 記録が3日以上空いた
    2. 連絡済みのあとに完了がない（2日以内）
    3. 未着手
    4. 一部完了
    5. それ以外

## 新ホーム（01・08）
- ◎ 5状態（はじめて・今日まだ・記録中・タスク完了・再開）、今日の記録、再開の統合（Resume 廃止）。詳細は docs/spec-instruction-diff.md
- ［仮］次の称号は連続日数の節目（7・30・100・365）で代用

## クラブ管理者の見える範囲・コイン（バッチ5）
- ◎ 生徒の詳細（10）：クラブ管理者には完了した配信タスクと記録の帯まで。教科の内訳・履歴の教科は運営だけ。DB でもクラブ管理者は教科・内容・コインを読めない（pgTAP 23）
- ◎ 運営の生徒詳細にコインの残高と台帳（理由・増減）を追加
- ◎ コイン台帳と付与（学習した日1・配信タスク10・15分集中5）はバッチ1〜で実装済み。二重付与なしを23で確認
- 未対応：デイリークエストのコイン付与（仕様書に額の定めがないため、表示のみ）

## 条件でもらえるバッジ（バッチ6、仕様書 5-4）
- ◎ バッジの定義（ストリーク3・7・30日、初めての教科5つ、15分チャレンジャー、集中のつみかさね10回、クラブミッション参加）と獲得判定。記録のたびに判定し、新しく得たものを記録の結果に返す
- ◎ 記録の瞬間（02）：バッジ獲得のときも全面のシートを出し、バッジ名を文字で示す（15分集中の達成シートも同様）
- ◎ コレクション（04）：獲得したバッジ（レアリティ・獲得日）と、これからもらえるバッジ（条件と n / goal、細い進捗線）
- ◎ 運営：生徒詳細にバッジ欄、アラート「バッジ獲得」に条件でもらえるバッジを含める（連続記録は節目のアラートがあるため除く）。クラブ管理者には見せない
- ◎ すでにいる生徒には、今の記録から付ける（画面・アラートは出さない）
- ［仮］朝活ハンターは「朝」の定義が未定のため入れていない。次の称号・バッジまでの残りは、連続記録のバッジ（3・7・30日）と［仮］100・365日で出す

## 導入の入口（バッチ7、仕様書「導入の流れ」）
- ◎ 学年は先に1タップで選ぶ（3×2のボタン）。表示名は LINE の名前が初期値で、変えられる。LINE の名前が取れているときは「学年を1つ選ぶだけで進めます」と案内する
- ◎ 初期値は整えて入れる（空白を詰める・制御文字を除く・20文字まで。code point で数える）。取れないときは空欄のまま
- ◎ LINE の名前の読み取りは本人と運営だけ（クラブ管理者・他の生徒は読めない。pgTAP 25）
- 要設定：LINE の名前を取るには、LIFF（LINE Developers）のスコープで profile を有効にする。無効でも導入は止まらず、表示名が空欄になるだけ

## タスク・ミッションの複製と一括配信（バッチ8、仕様書 画面11・13）
- ◎ タスクの複製：一覧の各行（配信中・予定・終了）の「複製する」で、名前・教科・目安・くり返し・対象の学年・報酬を引き継いだ作成フォームを開く（開始日は今日、期限日は空）
- ◎ 複数クラブへの一括配信：作成フォームでクラブを複数選べる（すべて選ぶ／選びなおす）。ボタンは「◯クラブに配信する」
- ◎ 学年への配信：対象の学年を選べる（空は全学年）。生徒への展開（sync_today_tasks）と、運営のアラート「配信タスクが未完了」を学年の対象に合わせる。一覧に「対象」を出し、今日の完了率の分母も対象の生徒だけにする
- ◎ 配信タスクの報酬：作成画面に「報酬のコイン」（標準10、0〜100）。これまで作成画面が報酬を送らず、配信タスクのコインが0のままだった不具合を直した。既存の配信タスクで0のものは10にそろえた
- ◎ ミッションの複製：各ミッションの「複製する」で、タイトル・数えるもの・目標・報酬を引き継ぎ、期間は同じ長さで今日から始める
- ◎ ミッションの複数クラブへの一括作成：1クラブずつ作り、期間が重なるクラブは理由を添えて残りを作る
- 未対応：学年ごとの「基本の週セット」（ラボプリのひな型からの作成）。ラボプリのひな型（教材ID・教科・学年・目安時間・報酬・QR用URL）の仕組みが先に要る

## クラブ管理者への週1メール「今週の記録」（バッチ9、仕様書「連絡」）
- ◎ 載せる内容は仕様書どおり：学習した人数／しばらく記録がない生徒の数／応援がまだの生徒の数／管理画面へのリンク。生徒の名前・教科・コインは載せない
- ◎ 集計は DB 関数 weekly_digest_data（サービス用のみ呼べる）。対象は送る日の前日までの7日間（月曜朝に送れば前の月〜日）。「記録がない」はアラート設定の日数（初期3日、休息日は数えない）、「応援がまだ」はその7日間にコメントも「見たよ」もない生徒
- ◎ 週ごとの送信済み記録（weekly_digest_log）で、同じ週の二重送信を防ぐ。生徒が0人・宛先が0件のクラブには送らない。LINE ログイン用の仮アドレス（.invalid）は宛先にしない
- 要設定：Edge Function weekly-digest のシークレット（DIGEST_SECRET・RESEND_API_KEY・MAIL_FROM・ADMIN_URL）、送信元ドメインの認証、毎週月曜の呼び出し（cron）。メール送信サービスは Resend を仮に採用［仮］

# バッチごとのメモ

## 新ホーム（01・08）
- ◎ 5状態（はじめて・今日まだ・記録中・タスク完了・再開）、今日の記録、再開の統合（Resume 廃止）。詳細は docs/spec-instruction-diff.md
- ［仮］次の称号は連続日数の節目（7・30・100・365）で代用

## クラブ管理者の見える範囲・コイン（バッチ5）
- ◎ 生徒の詳細（10）：クラブ管理者には完了した配信タスクと記録の帯まで。教科の内訳・履歴の教科は運営だけ。DB でもクラブ管理者は教科・内容・コインを読めない（pgTAP 23）
- ◎ 運営の生徒詳細にコインの残高と台帳（理由・増減）を追加

## 条件でもらえるバッジ（バッチ6）
- ◎ バッジ11種の定義と獲得判定、記録の瞬間（02）での表示、コレクションでの進み具合、運営の生徒詳細とアラート「バッジ獲得」、既存生徒の後付け
- ［仮］朝活ハンターは「朝」の定義が未定のため入れていない

## 導入の入口（バッチ7）
- ◎ 学年を先に1タップ。表示名は LINE の名前を整えて初期値に（空白を詰める・制御文字を除く・20文字まで）。LINE の名前の読み取りは本人と運営だけ（pgTAP 25）
- 設定：LIFF のスコープで profile を有効にする

## タスク・ミッションの複製と一括配信（バッチ8）
- ◎ タスクの複製、複数クラブへの一括配信、学年の対象（展開とアラートに反映）、配信タスクの報酬（標準10。これまで作成画面が報酬を送らず0のままだった不具合を直し、既存の0は10にそろえた）、ミッションの複製と複数クラブ一括作成

## 管理者への週1メール（バッチ9）
- ◎ 学習した人数／しばらく記録がない生徒の数／応援がまだの生徒の数／管理画面へのリンク。名前・教科・コインは載せない。対象は前日までの7日間。週ごとの送信済み記録で二重送信なし。生徒0人・宛先0件のクラブには送らない。LINE ログイン用の仮アドレスは宛先にしない
- 設定：Resend［仮］、シークレット（DIGEST_SECRET・RESEND_API_KEY・MAIL_FROM・ADMIN_URL）、送信元ドメインの認証、毎週月曜の cron（scripts/schedule-weekly-digest.sql）

## 文面の差し込み・クラブ管理者の追加解除・ふりかえり・CI（バッチ10）
- ◎ 文面の差し込み：{名前}（全種類）、{残り数}（未着手・配信タスクが未完了）、{連続日数}（連続記録が途切れた・節目）。種類ごとに使える言葉だけを保存でき、使えない言葉は保存時に理由つきで止める。値が取れないときは、置き換えずに残す（運営が表示で気づける）
- ◎ クラブ管理者の追加・解除（画面14、運営だけ）：メールアドレスで追加（認証ユーザーを用意し、ロールを club_admin に）。生徒・運営のアドレスは書き換えない。解除は所属を「退会」にする（履歴は残る）。1人が同時に所属できるクラブは1つのため、ほかのクラブの管理者は先に解除が要る（複数クラブを兼ねる人は、いまは作れない）。追加したら、本人が管理画面で自分のメールにログインリンクを送って入る
- ◎ ふりかえり（06）：連続記録の推移（直近12週。学習で+1、休息日は据え置き、空いた日で0、今日は崩さない）、休息チケット（持っている枚数・その期間に使った日数）
- ◎ GitHub Actions：PR と main への push で、型検査・テスト・Edge Function のテスト・ビルド、DB の適用・lint・pgTAP を検査
- 設定：club-admin 関数の反映（push-v17-batch10.ps1）。ALLOWED_ORIGINS は line-login と同じ値を使う

## 公式LINE の準備（バッチ11）
- ◎ 友だち状態：公式LINE の Webhook（follow / unfollow）を Edge Function line-webhook が受け、署名（X-Line-Signature）を確かめてから記録する。友だち追加はログインより先に起きるため、line_friends に残し、line_accounts ができたときに引き継ぐ。順序が入れ替わって届いた古い出来事では上書きしない
- ◎ 連絡の受け取り：生徒がコレクションの下で「受け取る／受け取らない」を切り替える。止めた生徒には、運営のアラートを出さない（出ていたものは次の生成で解消）。アプリの記録・応援には影響しない
- ◎ 運営の画面：アラートの行に「ブロック中」、生徒の詳細に「公式LINE」（友だち状態・連絡の受け取り）。クラブ管理者には見せない（DB でも読めない）
- 設定：LINE Developers の Messaging API チャネルで、Webhook URL を https://［プロジェクトREF］.supabase.co/functions/v1/line-webhook にして「Webhookの利用」をオン、検証（Verify）が成功することを確かめる。チャネルシークレットを LINE_MESSAGING_CHANNEL_SECRET として設定。ミニアプリと公式LINE が同じプロバイダーであること（ユーザー ID が一致する前提）
- 未対応：保護者同意の文面に「連絡を止められる」ことの一文（同意の取り直しになるため、文面を決めてから）

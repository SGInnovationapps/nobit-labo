## 手元で流す

```bash
bash tests/local/run.sh
```

「合格 314 ／ 不合格 0」（RLS）、「合格 55 ／ 不合格 0」（ログインの登録処理）、「合格 45 ／ 不合格 0」（入会申込）、「合格 21 ／ 不合格 0」（予定・お知らせの既読）、
続いて Deno のテストが「15 passed | 0 failed」、最後に「✔ すべて通りました」が出れば合格。
Deno がない環境では `test-auth.js` を飛ばし（その旨が出る）、全体は失敗にしない。
deno が PATH にないときは `DENO=/path/to/deno bash tests/local/run.sh`。`auth_rpc_test.sql` は拡張機能 dblink（PostgreSQL に同梱）を使う。
不合格があると × の行が一覧に出て、終了コードが 0 以外になる。
テストは最後にすべて巻き戻すので、データベースには何も残らない
（`auth_rpc_test.sql` の同時使用のテストだけは別の接続でデータを確定させ、最後に消す）。

## テーブルを増やしたとき

- 「他のクラブが見えないこと」の検査は、club_id を持つすべてのテーブルを自動で回る。
  新しいテーブルも、何もしなくても検査対象に入る
- 役割ごとの見え方（保護者に見せる／見せない など）を決めたら、
  `rls_test.sql` の該当する節にテストを1行足す
- `007_rls.sql` の最後の検査で、RLSの付け忘れ・ビューの security_invoker の付け忘れ・
  club_id のないテーブルがあると、マイグレーション自体が失敗する

ここが赤いまま進めると、情報漏れに直結する。
